# ThreatLens v2.0

### SOC Log Analysis, Threat Detection & Incident Correlation Platform

ThreatLens is a web-based cybersecurity investigation platform that analyzes supported security telemetry, detects suspicious behavior, correlates related security events into incidents, extracts indicators of compromise (IOCs), maps activity to MITRE ATT&CK, calculates investigation risk, enriches public IP addresses with threat intelligence, and generates SOC-style investigation reports.

## Key Features

- Upload `.log`, `.txt`, and `.pdf` files
- Paste security logs directly into the dashboard
- Automatic telemetry/source detection
- Modular security event parsing
- Behavioral detection rules
- Multi-event incident correlation
- Risk scoring from 0-100
- Executive investigation summaries
- MITRE ATT&CK mapping
- IOC and affected-asset extraction
- AbuseIPDB threat intelligence enrichment
- Chronological threat timeline
- Severity visualization
- Raw log viewer
- SOC PDF report generation
- CSV investigation export
- Unsupported-input detection

## Detection Capabilities

ThreatLens currently detects behaviors including:

- SSH brute-force attempts
- Successful login following repeated failures
- Web scanning activity
- Encoded PowerShell execution
- Suspicious download behavior
- Registry-based persistence
- DNS/C2 beaconing behavior
- Recovery inhibition
- Rapid file creation activity

## Incident Correlation

ThreatLens v2.0 goes beyond isolated alerts by correlating related detections occurring within relevant time windows.

Current scenarios include:

- Account Compromise
- Execution → Persistence
- DNS → C2 Beaconing
- Ransomware-Like Activity

For example, ransomware-like activity can correlate suspicious execution, recovery inhibition, and rapid file activity occurring on the same host into a higher-confidence incident.

## Built-In Attack Simulations

The dashboard includes five built-in scenarios:

1. Normal Activity
2. Account Compromise
3. Execution → Persistence
4. DNS → C2 Beaconing
5. Ransomware-Like Activity

These scenarios are processed through the same analysis pipeline as user-supplied telemetry. Detection results are generated by the engine rather than hardcoded into the interface.

## MITRE ATT&CK Mapping

Detected behaviors are mapped to relevant MITRE ATT&CK techniques, including examples such as:

- T1059.001 — PowerShell
- T1105 — Ingress Tool Transfer
- T1547.001 — Registry Run Keys / Startup Folder
- T1071.004 — DNS
- T1490 — Inhibit System Recovery
- T1486 — Data Encrypted for Impact

## Ransomware-Like Activity Detection

ThreatLens does not claim to predict ransomware before it occurs.

Instead, it identifies and correlates behaviors that can be consistent with ransomware activity, such as:

- Suspicious PowerShell execution
- Recovery inhibition
- Rapid file activity
- Multiple related signals occurring on the same host within a short time window

These signals can produce a high-confidence correlated ransomware-like incident for further analyst investigation.

## Supported Input

ThreatLens supports recognized security telemetry supplied through:

- `.log`
- `.txt`
- `.pdf`
- Pasted log data

Examples include Windows Sysmon, authentication, web, and process-related telemetry supported by the current parsers.

Unrecognized input is reported as unsupported rather than incorrectly classified as safe.

## Reports & Exports

ThreatLens generates:

- SOC Investigation PDF reports
- CSV investigation exports

Reports can include findings, incidents, affected assets, MITRE ATT&CK mappings, threat intelligence, timelines, recommendations, and overall risk.

python -m unittest discover -s tests -v

## How to Run

Install dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file for optional AbuseIPDB threat-intelligence enrichment:

```text
ABUSEIPDB_API_KEY=your_api_key_here
```

Run ThreatLens:

```bash
python app.py
```

Then open the local Flask application in your browser.

## Security & Privacy

- API credentials are loaded through environment variables and should never be committed to the repository.
- Uploaded data is analyzed for the current application session.
- Unsupported telemetry does not receive a false "safe" assessment.
